# Подготовка «Пазлы и картинки» к Яндекс Играм

## Два варианта сборки

- `npm run build` создаёт обычную браузерную версию без запроса SDK. Она работает локально и из ZIP по вложенному адресу.
- `npm run build:pages` создаёт версию для GitHub Pages с базовым путём `/My-game/`.
- `npm run build:yandex` создаёт отдельный ZIP-вариант: он загружает предоставляемый платформой `/sdk.js`, вызывает `YaGames.init()` **до чтения сохранений**, а затем запускает Phaser. Файл SDK не копируется в ZIP и не подменяется заглушкой.

Загрузка `/sdk.js` ограничена 12 секундами, а ожидание `YaGames.init()` — 20 секундами. При отказе или зависании игра запускается с локальным сохранением; предупреждение остаётся в консоли для диагностики. Ошибки отдельных методов `LoadingAPI` и `GameplayAPI` также выводятся как предупреждения и не прерывают игру.

Все три сборки используют одинаковые картины, уровни и формат сохранений. Ключи `mystic-puzzles-v1`, `mystic-puzzles-results-v1` и `mystic-puzzles-audio-v1` не менялись. Согласно [документации данных игрока](https://yandex.ru/dev/games/doc/ru/sdk/sdk-player), для загруженного архивом исходного кода SDK сам предоставляет надёжную оболочку `localStorage`; дополнительное облачное хранилище или обязательная авторизация не добавлены. После ошибки загрузки SDK игра использует прежнее локальное сохранение. Переключение аккаунта необходимо отдельно проверить в черновике платформы.

При временном отказе SDK доступ к платформенной оболочке сохранений может отсутствовать: локальный fallback не удаляет её данные, но синхронизация результатов, полученных во время такого отказа, после восстановления SDK **не подтверждена**. Это отдельный обязательный сценарий ручной проверки; при обнаружении расхождения нельзя считать выпуск готовым без решения по хранению данных.

## Методы и жизненный цикл

Интеграция следует [подключению SDK](https://yandex.ru/dev/games/doc/ru/sdk/sdk-about) и [разметке геймплея](https://yandex.ru/dev/games/doc/ru/sdk/sdk-game-events):

1. В Yandex-сборке динамически загружается `/sdk.js`, затем вызывается `YaGames.init()`; обычная и Pages-сборки SDK не запрашивают.
2. После первой отрисовки готового меню один раз вызывается `ysdk.features.LoadingAPI.ready()`.
3. После загрузки полной картины и создания деталей при начале уровня вызывается `GameplayAPI.start()`. При выходе из пазла или победе — `GameplayAPI.stop()`. Повторные отрисовки не дублируют эти вызовы.
4. Обработчики `game_api_pause`/`game_api_resume` останавливают таймер, ввод и звук и затем возобновляют игру. [Документация событий](https://yandex.ru/dev/games/doc/ru/sdk/sdk-events) говорит, что SDK сам согласует эти события с `GameplayAPI`; игра не посылает повторные ручные маркеры при каждом событии. При скрытии вкладки прежняя локальная обработка также продолжает работать.
5. Рекламные API из игры не вызываются. Платформа может автоматически показать рекламу при старте; события SDK уже обрабатывают такую паузу. По [пункту 1.12 требований](https://yandex.ru/dev/games/doc/ru/requirements/1/12), если первая версия выходит без монетизации, в комментарии разработчика к черновику нужно прямо указать это решение; стартовый блок платформы сам по себе не считается подключённой монетизацией. Для будущей монетизации нужны отдельное решение о местах показа, подключение в Консоли и проверка callback-ов рекламного API. Во время сборки деталей показывать рекламу не планируется.

Тесты с имитацией SDK проверяют вызовы и паузу, но **не заменяют запуск в Яндекс Играх**. Ошибка загрузки настоящего SDK выводится как предупреждение и не останавливает игру; в черновике её нужно расследовать, а не считать успешной интеграцией.

## Сборка и архив

```sh
npm ci
npm test
npm run build:yandex
npm run test:yandex:browser
npm run package:yandex
```

Для отдельной проверки именно содержимого ZIP можно распаковать его во временный каталог и запустить браузерный тест: `python3 -m zipfile -e release/puzzles-yandex-games.zip /tmp/puzzles-yandex-release` и `YANDEX_RELEASE_DIR=/tmp/puzzles-yandex-release npm run test:yandex:browser`. Workflow выполняет тот же шаг перед выдачей artifact.

Архив создаётся в `release/puzzles-yandex-games.zip`. Каталог `release/` игнорируется Git. Упаковщик проверяет, что это именно Yandex-сборка, `index.html` расположен в корне, названия файлов латинские и без пробелов, отсутствуют исходники/тесты, CRC исправен и распакованный размер меньше 100 МиБ. Ограничение Яндекс Игр — **100 МБ распакованных файлов** согласно [официальным требованиям, пункты 1.21–1.22](https://yandex.ru/dev/games/doc/ru/concepts/requirements).

GitHub Actions workflow `Build Yandex Games release archive` выполняет сборку и сохраняет файл как artifact `puzzles-yandex-games` на 14 дней. В PR откройте вкладку **Checks** → нужный запуск workflow → **Artifacts** и скачайте архив artifact; при скачивании GitHub может завернуть его во внешний ZIP. Для загрузки в Консоль используйте вложенный `puzzles-yandex-games.zip`. Workflow не публикует игру.

## Ручная проверка в черновике Яндекс Игр

1. Загрузите ZIP в черновик через Консоль разработчика, запустите именно черновик и откройте его с [debug-панелью](https://yandex.ru/dev/games/doc/ru/console/debug-panel) или с `?debug-mode=16`.
   Если выпуск без монетизации, в поле «Комментарий разработчика» черновика напишите: «Монетизация не предусмотрена, реклама в игре отсутствует». Это требуется для проверки пункта 1.12.
2. Убедитесь, что лоадер показывает актуальную инициализацию SDK (`IT`), затем Game Ready становится зелёным после появления меню. Проверьте отсутствие ошибок `/sdk.js`, `YaGames.init()` и ресурсов в консоли.
3. Начните уровень 1, проверьте `GameplayAPI.start`; вернитесь к выбору уровней и проверьте `stop`. Снова откройте уровень, соберите его, проверьте `stop` на победе и `start` на следующем уровне. Повторная отрисовка не должна добавлять вызовы.
4. Во время пазла переключите вкладку и вернитесь. Если появляется автоматическая реклама платформы, проверьте и её: звук и таймер должны остановиться, касание не должно двигать детали, после `game_api_resume` игра должна продолжиться с тем же прогрессом. Убедитесь, что музыка не включается вопреки сохранённой настройке.
5. Пройдите уровень, перезагрузите страницу и повторно откройте игру. Проверьте звёзды, доступность следующего уровня, галерею и настройки. Повторите без авторизации и после входа в аккаунт. Для тестового сохранения проверьте также финал 25-го уровня без открытия 26-го.
6. Откройте черновик на поддерживаемых телефоне и ПК. Проверьте касания, область safe area, отсутствие горизонтальной прокрутки и корректную загрузку всех 25 картин.

Снимки в `docs/screenshots/yandex-games-release/` сделаны из Chromium при локальном запуске с **тестовой имитацией SDK**, кроме снимка победы из того же локального игрового прогона. Они показывают реальный интерфейс и не подтверждают работу в черновике платформы.
